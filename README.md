# 국내주식 매수신호 스캐너 (무료 버전)

국내(KOSPI + KOSDAQ) 전체 상장종목을 매일 자동으로 스캔해서,
정배열 / RSI 과매도탈출 / MACD 골든크로스 / 거래량 급증 / 피보나치 지지
5가지 기술적 신호를 감지하고, 종목을 클릭하면 캔들차트·매수타점·공시까지 보여주는 100% 무료 프로젝트입니다.

- 데이터 소스: [FinanceData/fdr_krx_data_cache](https://github.com/FinanceData/fdr_krx_data_cache) — KRX 전종목 시세를 매일 GitHub에 캐싱해주는 공개 저장소.
  **KRX 사이트에 직접 접속하지 않기 때문에 GitHub Actions(해외 서버)에서도 안정적으로 동작합니다.**
- 자동 실행: GitHub Actions (매일 장마감 후, 무료). 하루치 스캔이 보통 1~2분 내로 끝남
- 호스팅: GitHub Pages (무료)
- 별도 서버·DB 없음 (JSON 파일들로만 모든 데이터 관리)
- 신호 없는 코스피·코스닥 시총 상위 300종목도 검색해서 조회 가능 (보유·관심종목 체크용)
- 종목 상세페이지: TradingView 캔들차트 + 매수타점/목표가/손절가 + 매수 적합도 별점 + 최근 공시(선택)

> ℹ️ 이전 버전은 pykrx로 KRX 서버에 종목당 직접 접속하는 방식이었는데, GitHub Actions의 해외 IP가
> KRX에 의해 계속 차단당해 실패했습니다. 지금 버전은 그 문제를 근본적으로 피해가는 구조입니다.

## 1. 리포지토리에 올리기

이 폴더 전체를 본인 GitHub 리포지토리에 push 하세요.

```bash
git init
git add .
git commit -m "init: 국내주식 매수신호 스캐너"
git branch -M main
git remote add origin https://github.com/<본인계정>/<리포지토리명>.git
git push -u origin main
```

## 2. GitHub Pages 활성화

1. 리포지토리 → **Settings → Pages**
2. Source: `Deploy from a branch` 선택
3. Branch: `main` / `/ (root)` 선택 후 저장
4. 몇 분 후 `https://<계정>.github.io/<리포지토리명>/` 에서 접속 가능

## 3. GitHub Actions 권한 확인

1. 리포지토리 → **Settings → Actions → General**
2. "Workflow permissions" 항목에서 **Read and write permissions** 선택 후 저장
   (이게 꺼져 있으면 Actions가 signals.json을 커밋/푸시하지 못합니다)

## 4. 첫 실행 (수동으로 한 번 돌려보기)

기본적으로는 평일 KST 16:30에 자동 실행되지만, 바로 확인해보고 싶다면:

1. 리포지토리 → **Actions** 탭
2. 왼쪽에서 `Update Stock Signals` 워크플로 선택
3. **Run workflow** 버튼 클릭

> GitHub 캐시에서 날짜별로 데이터를 받아오는 방식이라, 전체 종목(약 2,700개)을 스캔해도
> 보통 **1~2분 내**로 끝납니다. 완료되면 `data/signals.json`과 `data/history/*.json`이
> 자동으로 갱신되고, 대시보드에도 바로 반영됩니다.

## 5. 로컬에서 테스트하고 싶다면

```bash

```

실행 후 `data/signals.json`이 갱신되며, `index.html`을 브라우저로 직접 열어 확인할 수 있습니다.
(단, 로컬 파일을 `file://`로 열면 fetch가 막힐 수 있으니, 아래처럼 간단한 로컬 서버를 쓰는 걸 추천합니다.)

```bash

# 브라우저에서 http://localhost:8000 접속
```

## 신호 계산 기준 (update_stocks.py)

| 신호 | 조건 |
|---|---|
| 정배열 | 5일 이동평균 > 20일 이동평균 > 60일 이동평균 |
| RSI과매도탈출 | RSI(14)가 전일 30 이하 → 당일 30 초과로 반등 |
| MACD골든크로스 | MACD선이 전일 대비 당일 시그널선을 상향 돌파 |
| 거래량급증 | 당일 거래량이 최근 20일 평균 거래량의 2배 이상 |
| 피보나치XX%지지 | ZigZag로 찾은 최근 스윙 구간의 피보나치 되돌림(23.6~78.6%) 레벨에 현재가가 ±2% 이내로 근접 |

숫자(임계값)는 `update_stocks.py` 상단의 설정값 부분에서 바로 조정할 수 있습니다.

## 내 포트폴리오 (portfolio.html)

보유종목·수량·평단가를 입력하면 평가손익·수익률·비중을 계산해주고, 종목별 대응 전략(1·2차 매수가,
1·2차 목표가, 손절가, 파동위치, 차트패턴, 매수/매도 신호)까지 한 화면에서 보여줘요.

- **보유종목 데이터는 브라우저(localStorage)에만 저장돼요.** 서버로 전송되지 않고, 다른 기기·브라우저에서는 안 보여요.
- 현재가·신호 등 분석 데이터는 워치리스트(시총 상위 300 + `watchlist.txt`)에 있는 종목만 자동 매칭돼요.
  워치리스트 밖 종목을 추가하면, 상세 분석 대신 "watchlist.txt에 추가하세요" 안내와 복사 가능한 코드가 나와요.
- 종목 검색 자동완성도 같은 워치리스트 범위 안에서만 동작해요.

### 1차/2차 분할 매수·목표가

기존 매수타점/목표가를 확장해서, 조정 시 추가 매수를 고려할 수 있는 **2차 매수가(61.8% 되돌림)**와
더 공격적인 **2차 목표가(1.272배 확장)**를 함께 제공해요. 계산 로직은 `analyze_wave_and_levels()`에 있어요.

### 차트 패턴 체크리스트 (밥그릇 / 공구리 / 눌림목)

일봉 데이터를 규칙 기반으로 분석해서 아래 세 패턴을 자동으로 감지해요.

| 패턴 | 판별 기준 |
|---|---|
| 눌림목 | 20일선 상승중 + 60일선 위 유지 + 최근 20일 고점 대비 4~15% 하락 |
| 공구리(횡보다지기) | 최근 15거래일 고가·저가 폭이 평균가 대비 8% 이내 |
| 밥그릇(라운딩바텀) | 최근 50거래일 중 저점이 구간 중간 70% 안에 위치 + 고점 대비 10%↑ 하락 후 재상승 (1~4파는 저점 대비 회복 정도로 단순화) |

⚠️ 이건 엘리어트파동과 마찬가지로 **정성적인 차트 패턴을 숫자 규칙으로 근사한 것**이라, 실제 차트를
눈으로 보는 것과 100% 같지 않을 수 있어요. 임계값은 `update_stocks.py`의 `detect_pullback()`,
`detect_consolidation()`, `detect_cup_pattern()` 함수에서 조정할 수 있어요.

## 종목 상세 페이지

대시보드에서 종목 행을 클릭하면(또는 아래 "관심종목 직접 조회"에서) `detail.html?ticker=코드`로 이동해서:

- **TradingView 캔들차트** (일봉, 무료 위젯 임베드 — 최대 15분 지연 시세, 확대/보조지표 조절 가능)
- 매수타점/목표가/손절가를 겹쳐 그린 자체 라인 차트 (종가 + MA5/20/60)
- 거래량 차트
- **최근 공시 목록** (DART, 설정 시)

를 볼 수 있어요.

### 신호 없는 종목도 조회 가능 (워치리스트)

대시보드는 신호가 감지된 종목만 보여주지만, **코스피·코스닥 시가총액 상위 각 150개(총 300개)**는
신호가 없어도(`관망` 상태로) 항상 상세페이지 조회가 가능해요. 대시보드 상단의
**"관심종목 직접 조회"** 검색창에 보유·관심 종목명이나 티커를 입력하면 바로 찾을 수 있어요.

- 이 범위는 `update_stocks.py`의 `WATCHLIST_TOP_N`(기본값 150)으로 조정할 수 있어요. 숫자를 늘리면
  더 많은 종목을 커버하지만 저장소 용량과 실행 시간이 늘어나요.
- 범위 밖(시총 300위 밖 + 신호도 없음) 종목은 데이터가 없다고 안내돼요 — 매일 밤 계산되는 정적 사이트라
  "아무 종목이나 실시간 계산"은 지원하지 않아요.

### 커스텀 워치리스트 (`watchlist.txt`) — 중소형주 보유종목용

시가총액 상위 300에 안 들어가는 중소형주를 보유·관심 종목으로 갖고 계시면, 저장소 루트의
**`watchlist.txt`**에 종목코드를 한 줄씩 적어두세요. 시총 순위·신호 여부와 무관하게 항상
조회 가능 목록에 포함됩니다.

```
# 예시
347700   # 스피어
462350   # 이노스페이스
005930   # 삼성전자
```

`#` 뒤는 주석으로 처리돼요. 최근 상장 등으로 아직 65거래일치 데이터가 안 쌓인 종목은
전체 신호분석 대신 "데이터 부족" 안내와 함께 현재가·차트만 표시돼요(완전히 숨겨지지 않아요).

### 기준일 vs 실행 시각

상단바에 **"기준일"**(실제 시세가 반영된 마지막 거래일)과 **"실행"**(스크립트가 돌아간 시각)을
분리해서 보여줘요. 보통 같은 날이지만, GitHub Actions 실행이 지연되거나 데이터 소스가 아직
그날 데이터를 안 올렸을 때는 기준일이 하루 전일 수 있어요 — 이 경우 그게 정상 동작이에요.

### 최근 공시 (DART) 설정 방법 — 선택 사항

공시 기능은 금융감독원의 **OpenDART**(완전 무료, API 키 발급만 필요) 연동이에요. 키를 등록 안 해도
사이트는 정상 동작하고, 공시 섹션에만 "설정되지 않았다"는 안내가 뜹니다.

1. https://opendart.fss.or.kr 에서 회원가입 후 [인증키 신청/관리]에서 무료 API 키 발급 (5분 소요, 승인은 보통 즉시~몇 시간 내)
2. 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
3. Name: `DART_API_KEY`, Value: 발급받은 키 붙여넣기 → **Add secret**
4. 그다음 **Actions → Run workflow**로 재실행하면 자동으로 공시 데이터가 함께 저장돼요.

> ⚠️ 이 DART 연동 부분은 제 작업 환경에서 opendart.fss.or.kr 접속이 막혀 있어서 실제 응답으로
> 직접 검증하지 못했어요. API 스펙 문서 기준으로 작성했으니, 키 등록 후 Actions 로그에서
> 정상적으로 공시가 들어오는지 꼭 확인해주시고, 에러가 나면 로그를 공유해주세요.

### 파동 위치 / 매수타점 / 목표가 / 손절가

상세페이지에는 아래 정보도 함께 표시돼요.

- **파동 위치**: `일봉(종가) 기준 · ZigZag 8% 스윙 전환점`으로 나눈 구간을 순서대로 세서 "상승 O파 진행 중"처럼 표시
- **매수타점**: 현재 상승 구간의 38.2% 되돌림 지점 (조정 시 매수 관점)
- **목표가**: 직전 하락폭 대비 1.272배 확장 지점
- **손절가**: 이번 상승의 시작점(직전 스윙 저점) 대비 2% 아래

> ⚠️ 이건 정통 엘리어트파동 이론(파동 간 피보나치 비율, 3파 최단파동 금지 등 세부 규칙)을
> 전부 검증한 게 아니라, ZigZag 스윙 전환점을 기준으로 순서를 세는 **단순화된 방식**이에요.
> 상세페이지 하단에 이 기준이 항상 함께 표시됩니다. 임계값(`ZIGZAG_THRESHOLD`)이나 확장 비율은
> `update_stocks.py`의 `analyze_wave_and_levels()` 함수에서 조정할 수 있어요.

### 매수 적합도 별점 (★1~5)

신호 개수·파동 방향·RSI 과매수 여부를 종합해서 참고용 별점과 라벨(매수 적합/관심 필요/관망)을
보여줘요. 계산 로직은 `update_stocks.py`의 `compute_rating()` 함수에 있고, 가중치는 자유롭게 조정 가능해요.

### 새로고침 버튼 — 알아두어야 할 한계

상단의 "새로고침" 버튼은 **이미 계산되어 있는 최신 `data/signals.json`을 다시 불러오는 것**이지,
그 자리에서 실시간으로 재계산하는 게 아니에요. 데이터 자체가 장마감 후 하루 1회 갱신되는 구조라서
(원본 데이터 소스가 EOD 데이터), 더 자주 눌러도 장중에는 값이 바뀌지 않아요(정상 동작).
페이지는 3분마다 자동으로도 조용히 새 데이터가 있는지 확인해요.

> 공개 웹사이트에 "지금 당장 GitHub Actions를 재실행"하는 버튼을 넣으려면 Actions를 트리거할 수 있는
> 토큰이 필요한데, 이를 클라이언트 코드에 넣으면 누구나 탈취해서 저장소를 조작할 수 있어 보안상
> 넣지 않았어요. 정말 그 순간 재계산하고 싶다면 Actions 탭에서 직접 **Run workflow**를 눌러주세요.

## 커스터마이징 아이디어

- `MIN_SCORE_TO_INCLUDE`(기본값 2)를 3 이상으로 올리면 더 신뢰도 높은 소수 종목만 남길 수 있어요. 1로 낮추면 너무 많아져서(전체의 절반 이상) 추천하지 않아요.
- `WATCHLIST_TOP_N`(기본값 150)을 늘리면 신호 없이도 조회 가능한 종목 범위가 넓어져요.
- 신호를 더 추가하고 싶다면 `analyze_stock()` 함수 안에 조건을 하나 더 추가하면 됩니다.
